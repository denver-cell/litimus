## What the signals actually measure

Sentence-length variation, vocabulary spread, stock transitional phrases, repeated three-word sequences, em-dash frequency, structural symmetry — all of it built around how sentences work in prose. Code doesn’t have sentences, transitions, or the kind of vocabulary spread that means anything comparable.

## Running a code submission through Litimus anyway

If you paste code into a text detector, you’ll get a score, because the tool will still measure something — it just won’t be measuring anything relevant. Treat any such result as meaningless rather than inconclusive; it isn’t answering the question you’re asking.

## What actually helps for code

Version-history tools built for the purpose, live coding checks, and asking a student to walk through and modify their own submission in front of you — a request that a copied or generated solution is much harder to satisfy convincingly than an honest one.

## The one place text detection still applies

Comments, documentation, and written explanations submitted alongside code are prose, and a detector can meaningfully say something about those — just not about the code itself.
